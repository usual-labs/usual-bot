# UsualUI: components

## Implemented today

RootView owns top-level routing; ContactsSplitView handles selection; ContactList/ContactRow own roster; ThreadPane, Composer and TranscriptView own conversation presentation; RoomPane/NewRoomSheet own rooms; ProfilePanel owns agent profile/routine UI.

On the Mac, ContactsSplitView lays the sidebar out itself (an HStack, not NavigationSplitView): the list's width is stored in `@AppStorage("sidebarWidth")` (78–380 pt), a drag edge resizes it live, and under 220 pt the list renders as the 78 pt avatar rail (`ContactRow(compact: true)`), snapping to the rail or back to 300 pt when the drag ends. A window that leaves the chat under 360 pt shows the rail too. Search and New Room are Liquid Glass circles in the window toolbar, placed at the sidebar's right edge and level with the window buttons (see 07-known-issues.md). The profile panel's close button is a trailing toolbar item, shown only while the panel is open. In the message box, Return sends and Shift+Return inserts a line break at the cursor (`MessageBox.insertLineBreak`). iPhone keeps NavigationSplitView: the chat list is a plain full-width `List` on the chat colour (`Theme.pane`; the Mac sidebar uses `Theme.window`) with no title, the gateway status dot top-left (`footer(true)`) and New Room top-right, and search at the bottom. `chatBars` puts the name pill in the navigation bar (`.principal`, beside the back button) on iPhone and in a top inset on the Mac; it owns both bars' margins. The profile panel is an `.inspector`, which iPhone shows as a sheet. TranscriptView and RoomPane scroll inside `ConversationScroll`, which opens at an end marker and returns there when `reload` (the chat's `transcriptLoad`) changes. MarkdownView gives bold, italic and inline-code runs their own fonts at the block's size (see 07-known-issues.md). ApprovalCard shows its choices in a row, or on iPhone as full-width buttons with "Allow once" on top. QuickMessageView (QuickMessage/) is the ⌥Space panel's content.
