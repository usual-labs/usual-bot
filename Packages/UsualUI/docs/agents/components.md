# UsualUI: components

## Implemented today

RootView owns top-level routing; ContactsSplitView handles selection; ContactList/ContactRow own roster; ThreadPane, Composer and TranscriptView own conversation presentation; RoomPane/NewRoomSheet own rooms; ProfilePanel owns agent profile/routine UI.

On the Mac, ContactsSplitView lays the sidebar out itself (an HStack, not NavigationSplitView): the list's width is stored in `@AppStorage("sidebarWidth")` (78–380 pt), a drag edge resizes it live, and under 220 pt the list renders as the 78 pt avatar rail (`ContactRow(compact: true)`), snapping to the rail or back to 300 pt when the drag ends. A window that leaves the chat under 360 pt shows the rail too. Search and New Room are Liquid Glass circles in the window toolbar, placed at the sidebar's right edge and level with the window buttons (see 07-known-issues.md). The profile panel's close button is a trailing toolbar item, shown only while the panel is open. In the message box, Return sends and Shift+Return inserts a line break at the cursor (`MessageBox.insertLineBreak`). iPhone keeps NavigationSplitView: the chat list is a plain full-width `List` on the chat colour (`Theme.pane`; the Mac sidebar uses `Theme.window`) with no title, the gateway status dot top-left (`footer(true)`) and New Room top-right, and search at the bottom. `chatBars` puts the name pill in the navigation bar (`.principal`, beside the back button) on iPhone and in a top inset on the Mac; it owns both bars' margins. The profile panel is an `.inspector`, which iPhone shows as a sheet. TranscriptView and RoomPane scroll inside `ConversationScroll`, which opens at an end marker and returns there when `reload` (the chat's `transcriptLoad`) changes. Attachments (Thread/Attachments.swift): in chats (not rooms) the message box starts with a + button (`AttachButton`, a grey circle the size of Send: a file picker on the Mac; Photo Library, camera and Files on iPhone), drop anywhere on the chat, and on the Mac pasted files or images. Waiting files show as `AttachmentChips` inside the box; Send then uploads them with the text (spinner while uploading) and the draft stays if an upload fails. HEIC/HEIF/TIFF are converted to JPEG (ImageIO) because the gateway takes only PNG, JPEG, GIF, WebP and BMP as images. `UserBubble` shows a message's `@image:`/`@file:` lines as `AttachmentTile`s above the text: a thumbnail when this device has the bytes (`sentImages` environment), otherwise the name. Images in replies (Thread/Media.swift): `MarkdownBlock.parse` turns `MEDIA:/path` lines and lines that are only an absolute image path (outside code fences) into `.media` blocks, shows image paths named inside a paragraph or list item as images under it (`imagePaths(in:)`: absolute paths ending in png/jpg/gif/webp/bmp/heic, not URLs or `~` paths), and Markdown images into `.image` (web) or `.media` (local path) blocks. `ReplyImage` loads them (gateway files through the `media` environment value as the `mediaProfile`, set per chat and per room reply author; web images directly), shows them inline up to 420×360 (aspect-fit and capped at that width, so they shrink to fit a narrower column), and opens `MediaViewer` (full size, Share, Save on the Mac). Non-image `MEDIA:` files show as a pill with a button that fetches the file and then offers Share. Sent images without local bytes load from the gateway into their tiles. Dictation (Thread/Dictation.swift): an empty message box shows a mic in Send's place (chats and rooms); tapping it asks for speech recognition and the microphone the first time, then words appear in the box as you speak, after whatever was typed (`Dictation.merge`). The button turns into a stop button with a ring that follows your voice; tapping it, sending, or the recognizer ending stops listening. `SFSpeechRecognizer` with `requiresOnDeviceRecognition` when the device supports it; on iPhone the audio session is set to record and released afterwards. Denied permissions or failures show a line under the box (with Open Settings for permissions). The user confirmed dictation on the Mac (24 October 2026); real speech on iPhone hasn't been tried. Suggestion menu (Thread/SlashMenu.swift): `SuggestionMenu` above the message box lists either the `/` menu (chats: a word starting with `/` as the last word typed, at the start or after a space or line break (`MessageBox.slashWord(in:)`; letters, digits, `-` and `_` only, so paths don't open it), reloads the thread's commands and lists every match, names starting with the query first, each with an icon (✦ `sparkles` for skills, ⌘ `command` for commands) and its description; seven rows show and the rest scroll, Up/Down scrolling the highlight into view) or the `@` menu (rooms: members). Up and Down move the highlight (wrapping), Return or Tab picks it, Escape or a click/tap on the conversation (`ChatBars`' `conversationTaps` environment value) closes the menu until the text changes; on the Mac the pointer also highlights. Picking replaces that word with `/name ` or `@handle `, keeping the text before it. Only a message that starts with a command runs it; a `/skill` named later is sent as written, as in the official app. A command's `prefill` (from /retry) replaces the box's text. Command output (TranscriptView.swift): a `.output` item renders as `CommandOutput`, monospaced, unwrapped (columns line up), scrolling sideways when wide, on a soft rounded background, with Copy from the message actions. Background tasks (Thread/SideCards.swift, TranscriptView.swift): `Composer` shows one `BackgroundTasksBar` above the side-question cards while any `thread.backgroundTasks` run (glass capsule, spinner, one line: "Working in the background: <task>", or "N tasks working in the background: a · b"; the Mac tooltip lists them all); a finished task's `.background` item renders in `ItemView` as a reply (`MessageRow`, so Copy works) with a "Background task: …" label over its Markdown. `HermesKit.BackgroundTask` is spelled out in UsualUI because SwiftUI has its own `BackgroundTask`. Side questions (Thread/SideCards.swift): `Composer` stacks a `SideQuestionCard` per `thread.sideQuestions` above the message box: a glass card with "Side question", the question on one line, ✕, and the answer as Markdown (scrolling past 220 pt), a spinner ("Thinking on the side…") while waiting, or "Couldn't answer: …". Context meter (Thread/ModelControls.swift, `ContextMeter`): first in the model and thinking row once `thread.usage?.context` is known: a 9 pt ring filled to the percentage (amber `Theme.needsYouInk` from 80%) and "38%" in the row's light style, a spinner while compressing. Its menu lists the context ("~" when Hermes estimated it), this chat's tokens and calls, compressions (plurals inflected), and Compress Conversation (disabled unless `thread.canCompress`). `ModelControls` loads models and usage together when the chat attaches. Model and thinking (Thread/ModelControls.swift): in chats, `Composer` puts `ModelControls` under the message box, on the right, once the thread knows its model: two quiet text menus (10 pt light, secondary ink at 70%, small chevrons) in a 16 pt row with `ModelControls.gap` (2 pt) above it and, through `chatBars(bottomPadding:)`, below it: 20 pt in all, the same as the box's side margin, so the box sits as far from the window's bottom edge (iPhone: the safe area's edge) as from the sides; chats without a known model and rooms keep the usual bottom margin (Mac 14, iPhone 12). The menus show the model (ID with the vendor folder dropped: `x-ai/grok-5` → `grok-5`) and the thinking level ("Default thinking" until a level is picked; hidden when the catalog says the model doesn't reason). Same on Mac and iPhone. The model menu lists the current provider's models as an inline picker (current ticked) and other providers as submenus; it loads `model.options` when the chat attaches. The thinking menu is an inline picker, Off…Ultra. A pricier model asks first in an alert (Switch / Keep); a failed switch shows an alert. On iPhone menus that open upward list their items in reverse (system behaviour). The profile panel has a Skills tab (Profile/SkillsView.swift) between Routines and Machine: skills most used first, each with a switch. Message actions (Thread/MessageActions.swift): `ItemView` wraps your messages, replies and room replies in `MessageRow`. On the Mac, hovering the message itself (not the empty row beside it; the bar stays up for 250 ms after the pointer leaves so it can reach the bar, and while over the bar) shows a glass bar beside the message (right of a reply, left of your bubble; its 104 pt slot is always reserved so nothing moves): React (chats only; quick 👍 👎 ❤️ 😂 🎉 and more behind +), Reply, and More › Copy. On iPhone a long press opens the same actions as a context menu (emoji as a palette row). Reactions show as pills under the message; yours are outlined and tapping one removes it. In chats, your last message also offers Edit and Undo (More menu on the Mac, long-press menu on iPhone; `MessageActions.canRewind`, true for `thread.lastSent` while `thread.canRewind`). Edit sets the box's text through `thread.prefill` and shows a `ReplyChip(text:cancelLabel:)` "Editing your last message" (✕ clears the box); `Composer.send` then calls `thread.edit` (or a plain send if a reply started meanwhile). Undo is destructive-styled and runs `thread.undo()` at once. Reply puts a `ReplyChip` in the message box ("Reply…") and sends `> Author: excerpt` before your text (in rooms with `@handle`, so only that agent answers); `UserBubbleContent` shows a sent quote inside the bubble. Chats and rooms provide the actions through the `messageActions` environment value. MarkdownView gives bold, italic and inline-code runs their own fonts at the block's size (see 07-known-issues.md). ApprovalCard shows its choices in a row, or on iPhone as full-width buttons with "Allow once" on top. QuickMessageView (QuickMessage/) is the ⌥Space panel's content.
