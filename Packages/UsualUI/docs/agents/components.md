# UsualUI: components

## Implemented today

RootView owns top-level routing; ContactsSplitView handles selection; ContactList/ContactRow own roster; ThreadPane, Composer and TranscriptView own conversation presentation; RoomPane/NewRoomSheet own rooms; ProfilePanel owns agent profile/routine UI.

On the Mac, ContactsSplitView lays the sidebar out itself (an HStack, not NavigationSplitView): the list's width is stored in `@AppStorage("sidebarWidth")` (78–380 pt), a drag edge resizes it live, and under 220 pt the list renders as the 78 pt avatar rail (`ContactRow(compact: true)`), snapping to the rail or back to 300 pt when the drag ends. A window that leaves the chat under 360 pt shows the rail too. Search and New Room are Liquid Glass circles in the window toolbar, placed at the sidebar's right edge and level with the window buttons (see 07-known-issues.md). The profile panel's close button is a trailing toolbar item, shown only while the panel is open. In the message box, Return sends and Shift+Return inserts a line break at the cursor (`MessageBox.insertLineBreak`). iPhone keeps NavigationSplitView: the chat list is a plain full-width `List` on the chat colour (`Theme.pane`; the Mac sidebar uses `Theme.window`) with no title, the gateway status dot top-left (`footer(true)`) and New Room top-right, and search at the bottom. `chatBars` puts the name pill in the navigation bar (`.principal`, beside the back button) on iPhone and in a top inset on the Mac; it owns both bars' margins. The profile panel is an `.inspector`, which iPhone shows as a sheet. TranscriptView and RoomPane scroll inside `ConversationScroll`, which opens at an end marker and returns there when `reload` (the chat's `transcriptLoad`) changes. Attachments (Thread/Attachments.swift): in chats (not rooms) the message box starts with a + button (`AttachButton`, a grey circle the size of Send: a file picker on the Mac; Photo Library, camera and Files on iPhone), drop anywhere on the chat, and on the Mac pasted files or images. Waiting files show as `AttachmentChips` inside the box; Send then uploads them with the text (spinner while uploading) and the draft stays if an upload fails. HEIC/HEIF/TIFF are converted to JPEG (ImageIO) because the gateway takes only PNG, JPEG, GIF, WebP and BMP as images. `UserBubble` shows a message's `@image:`/`@file:` lines as `AttachmentTile`s above the text: a thumbnail when this device has the bytes (`sentImages` environment), otherwise the name. Images in replies (Thread/Media.swift): `MarkdownBlock.parse` turns `MEDIA:/path` lines and lines that are only an absolute image path (outside code fences) into `.media` blocks, shows image paths named inside a paragraph or list item as images under it (`imagePaths(in:)`: absolute paths ending in png/jpg/gif/webp/bmp/heic, not URLs or `~` paths), and Markdown images into `.image` (web) or `.media` (local path) blocks. `ReplyImage` loads them (gateway files through the `media` environment value as the `mediaProfile`, set per chat and per room reply author; web images directly), shows them inline up to 420×360, and opens `MediaViewer` (full size, Share, Save on the Mac). Non-image `MEDIA:` files show as a pill with a button that fetches the file and then offers Share. Sent images without local bytes load from the gateway into their tiles. Dictation (Thread/Dictation.swift): an empty message box shows a mic in Send's place (chats and rooms); tapping it asks for speech recognition and the microphone the first time, then words appear in the box as you speak, after whatever was typed (`Dictation.merge`). The button turns into a stop button with a ring that follows your voice; tapping it, sending, or the recognizer ending stops listening. `SFSpeechRecognizer` with `requiresOnDeviceRecognition` when the device supports it; on iPhone the audio session is set to record and released afterwards. Denied permissions or failures show a line under the box (with Open Settings for permissions). The user confirmed dictation on the Mac (24 October 2026); real speech on iPhone hasn't been tried. Suggestion menu (Thread/SlashMenu.swift): `SuggestionMenu` above the message box lists either the `/` menu (chats: typing `/` at the start reloads the thread's commands and lists up to six matches, names starting with the query first, with descriptions and a Skill tag) or the `@` menu (rooms: members). Up and Down move the highlight (wrapping), Return or Tab picks it, Escape or a click/tap on the conversation (`ChatBars`' `conversationTaps` environment value) closes the menu until the text changes; on the Mac the pointer also highlights. Picking fills in `/name ` or `@handle `. A command's `prefill` (from /retry) replaces the box's text. The profile panel has a Skills tab (Profile/SkillsView.swift) between Routines and Machine: skills most used first, each with a switch. Message actions (Thread/MessageActions.swift): `ItemView` wraps your messages, replies and room replies in `MessageRow`. On the Mac, hovering shows a glass bar beside the message (right of a reply, left of your bubble; its 104 pt slot is always reserved so nothing moves): React (chats only; quick 👍 👎 ❤️ 😂 🎉 and more behind +), Reply, and More › Copy. On iPhone a long press opens the same actions as a context menu (emoji as a palette row). Reactions show as pills under the message; yours are outlined and tapping one removes it. Reply puts a `ReplyChip` in the message box ("Reply…") and sends `> Author: excerpt` before your text (in rooms with `@handle`, so only that agent answers); `UserBubbleContent` shows a sent quote inside the bubble. Chats and rooms provide the actions through the `messageActions` environment value. MarkdownView gives bold, italic and inline-code runs their own fonts at the block's size (see 07-known-issues.md). ApprovalCard shows its choices in a row, or on iPhone as full-width buttons with "Allow once" on top. QuickMessageView (QuickMessage/) is the ⌥Space panel's content.
