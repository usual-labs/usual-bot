# HermesKit: user and caller surface

## Implemented today

Public model types in Sources/HermesKit include AppModel, Contact, ChatThread, RoomThread, Routine and authentication/address types. ChatThread.send(_:attachments:) uploads `Attachment`s first (images through `image.attach_bytes`, which queues them for the next turn; every other file, PDFs included, through `file.attach`, which returns an `@file:` reference), then submits; a failed upload sends nothing, takes queued images back with `image.detach` and adds a notice. A sent message carries `@image:`/`@file:` lines after its text, as the gateway's history does; `AttachmentRef.split` reads them back. `sentImages` keeps this run's uploaded image bytes by gateway path for thumbnails. Limits: 25 MB per image (the gateway's), 50 MB per file. Slash commands (Chat/ChatThread+Commands.swift): `ChatThread.loadCommands()` reads `commands.catalog` into `commands` (skills, quick and plugin commands, and the built-ins /retry, /undo, /compress, /plan, /goal and /learn; other registry commands drive the terminal UI and are left out). Sending a message that starts with a known command runs `command.dispatch` instead of `prompt.submit`: `skill`/`send` submit the returned message while the bubble shows the typed or `display` text, `exec`/`plugin` show output as a notice, `prefill` sets `prefill` for the message box, `alias` re-runs its target. Unknown `/words` go out as ordinary text. `SkillList` (`AppModel.skills(for:)`) reads `GET /api/skills?profile=` (every skill, with `enabled`, usage and provenance) and switches one with `PUT /api/skills/toggle`, moving the switch back on failure. Transcript items carry the store's `rowID` and `reactions` (`Reaction`: emoji, by you or the agent) from history (`row_id`, `display_metadata.reactions`). `ChatThread.react(_:to:)` calls `message.react` (by `row_id`, or `newest_role` for a message that arrived live), shows the change at once, applies the gateway's list and reverts with a notice on failure; Tapback rules (one per author, same emoji clears). Reactions are display-only in Hermes: the agent's model never sees them. Rooms have no reaction call. Undo and edit (Chat/ChatThread+Edit.swift): `lastSent` is your newest message; `canRewind` is true between replies when nothing uploads or rewinds (`isRewinding`). `undo()` calls `session.undo` and, when it `removed` anything, reloads with `session.history` (`replaceTranscript(with:)`, bumping `transcriptLoad`), else cuts the local transcript (`ThreadState.rewind(from:)`); a refusal or nothing to undo becomes a notice. `edit(_:)` is undo then `send`; a failed undo puts the text in `prefill`. `editableText(of:)` keeps the text and `@file:` lines, not `@image:` lines. Model and thinking (Chat/ChatModel.swift): `ChatThread.model` (`ChatModel`: name, provider, `ReasoningLevel?`) comes from the `info` of `session.resume`/`session.create` and from `session.info` events (`reasoning_effort` "" = provider default → `nil`, "none" = `.off`). `loadModels()` reads `model.options {session_id}` into `modelProviders` (`ModelProvider`: slug, name, `featured_models` when an aggregator has them else `models`, `reasons(_:)` from `capabilities`). `setModel(_:provider:confirmed:)` sends `config.set key:model value:"<model> --provider <slug> --session"` (this chat only; config.yaml untouched) and returns `ModelSwitch` (`.switched`, `.next` when deferred during a reply, with a notice; `.needsConfirmation(message)` for `confirm_required`, resend with `confirmed` → `confirm_expensive_model`; `.failed`); a `warning` becomes a notice. `setReasoning(_:)` sends `config.set key:reasoning`, shows the level at once and reverts with a notice on failure. `AppModel.media` (`MediaStore`) reads files agents name in chats through `GET /api/fs/read-data-url?path=&profile=` (16 MB cap; `/api/media` only serves the default profile's image folders), keeps the last 40 in memory and shares one request per file; `AppModel.describe` words errors for the UI. AppModel exposes restore/signIn, `AppModel.demo()` (Debug only: a signed-in model with made-up agents, chats, a pending approval, a room and routines, built from the internal `sample` helpers; it never connects), `setForeground(_:)` (closes the socket while the app is in the background and reconnects on return, reattaching every chat; the iOS app calls it from `scenePhase`) and per-contact thread/room/routine operations. GatewayConnector mints a WebSocket ticket, opens /api/ws, waits for gateway.ready, then advertises server_requests capabilities. JSONRPCChannel owns socket requests and responses. OfflineCache persists a Codable roster/thread snapshot; KeychainTokenStore persists token sets per gateway.
