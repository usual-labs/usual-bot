# HermesKit: user and caller surface

## Implemented today

Public model types in Sources/HermesKit include AppModel, Contact, ChatThread, RoomThread, Routine and authentication/address types. ChatThread.send(_:attachments:) uploads `Attachment`s first (images through `image.attach_bytes`, which queues them for the next turn; every other file, PDFs included, through `file.attach`, which returns an `@file:` reference), then submits; a failed upload sends nothing, takes queued images back with `image.detach` and adds a notice. A sent message carries `@image:`/`@file:` lines after its text, as the gateway's history does; `AttachmentRef.split` reads them back. `sentImages` keeps this run's uploaded image bytes by gateway path for thumbnails. Limits: 25 MB per image (the gateway's), 50 MB per file. Slash commands (Chat/ChatThread+Commands.swift): `ChatThread.loadCommands()` reads `commands.catalog` into `commands` (skills, quick and plugin commands, and the built-ins /retry, /undo, /compress, /plan, /goal and /learn; other registry commands drive the terminal UI and are left out). Sending a message that starts with a known command runs `command.dispatch` instead of `prompt.submit`: `skill`/`send` submit the returned message while the bubble shows the typed or `display` text, `exec`/`plugin` show output as a notice, `prefill` sets `prefill` for the message box, `alias` re-runs its target. Unknown `/words` go out as ordinary text. `SkillList` (`AppModel.skills(for:)`) reads `GET /api/skills?profile=` (every skill, with `enabled`, usage and provenance) and switches one with `PUT /api/skills/toggle`, moving the switch back on failure. Transcript items carry the store's `rowID` and `reactions` (`Reaction`: emoji, by you or the agent) from history (`row_id`, `display_metadata.reactions`). `ChatThread.react(_:to:)` calls `message.react` (by `row_id`, or `newest_role` for a message that arrived live), shows the change at once, applies the gateway's list and reverts with a notice on failure; Tapback rules (one per author, same emoji clears). Reactions are display-only in Hermes: the agent's model never sees them. Rooms have no reaction call. Usage (Chat/ChatThread+Usage.swift): `ChatThread.usage` (`ChatUsage`: `context` (used, max, percent, estimated; `nil` until the gateway knows), input, output, calls, compressions) comes from `loadUsage()` (`session.usage`) and from `message.complete`'s `usage` in `apply`. `compress()` (`canCompress`: between replies, `isCompressing`) calls `session.compress` (300 s timeout), takes its `usage`, keeps the transcript and adds a notice with before/after tokens (`tokens(_:)` formats 18.4k / 1.3M), or "nothing to compress", or the refusal. Hermes reports no cost. Commands (Chat/ChatThread+Commands.swift): `commands(in:)` turns `commands.catalog` into the `/` menu: skills (`.skill`), quick and plugin commands, and the registry's built-ins whose `commands[name].desktop` is null (offered in the official app; `hidden`, `terminal`, `advanced`, `settings` stay out), minus `notInMessenger` (/new, /resume, /sessions, /branch, /title, /handoff, /import, /profile: they'd switch, rename or split the one Bot Chat; /skin, /pet, /hatch, /palette, /timestamps, /suggestions: terminal looks). `run` tries `command.dispatch` first; a 4018 "not a quick/plugin/bundle/skill command" falls back to `slash.exec {session_id, command}` (Hermes's command worker; the gateway mirrors model/fast/compress and answers status/usage/context/help from the live chat), whose `output` becomes `.output` (terminal text) after your `/command` bubble, `type: send` sends its message, and `warning` a notice. Quick-command `output` is `.output` too. `/reasoning [level] [--global]` is handled here instead (`runReasoningCommand`): `config.set key: reasoning` on this chat (or `scope: global`), since the worker's /reasoning wouldn't reach the live chat; no level shows the current one. Background tasks (Chat/ChatThread+Background.swift): `send` routes `/bg <text>` and `/background <text>` (`backgroundTask(in:)`, via the shared `words(after:in:)`) to `runInBackground(_:)`, which appends a `BackgroundTask` (local ID) to `backgroundTasks` and calls `prompt.background`, swapping in the `task_id` (a refusal removes it and adds a notice). `background.complete` (routed in `apply`) removes the task (by ID, else the oldest still local), appends `TranscriptItem.Content.background(task:result:)` via `ThreadState.addBackgroundResult` (or a notice for `error: …`), bumps `unreadCount` when the chat isn't visible, and calls `backgroundTaskFinished`, which `AppModel` forwards to its public `backgroundTaskFinished(contact, task, result)` hook. Recovery (Chat/ChatThread+Recovery.swift): each event's `seq` raises `lastSeq`; `AppModel` hands every chat the socket's `replayEpoch` and a `storedAnswer(taskID)` closure (`GET /api/sessions/{id}/messages?profile=&order=latest&limit=5&inline_images=false`; the newest row, if `assistant` text without tool calls). `attach` tells `recoverMissed(rejoined:)` whether it's the same live session and epoch with `lastSeq > 0`: then `session.events.since` replays `btw.complete`/`background.complete` (not when `truncated` or the epoch differs); otherwise waiting side questions become `.failed` and unconfirmed `local-` tasks are dropped with a notice. Then waiting tasks are checked every 20 s while attached. `backgroundResults` (taskID, task, result, date; last 50) survive transcript rebuilds via `ThreadState(history:…, kept:)`, which slots them in by timestamp; a task's result is applied once. `CachedThread` (Chat/CachedThread.swift) also keeps side questions, tasks and the last 20 results (optional fields, so older caches load). Side questions (Chat/ChatThread+SideQuestions.swift): `send` routes `/btw <text>` (`sideQuestion(in:)`) to `askOnTheSide(_:)` before steering or commands, so it works mid-turn. It appends a `SideQuestion` (`.waiting`, local ID) to `sideQuestions` and calls `prompt.btw`, swapping in the returned `task_id`; `btw.complete` events (routed in `apply`) set `.answered` or `.failed` (`error: ` prefix), matching by task ID, else a waiting question with the same text, else appending (asked elsewhere). `dismiss(_:)` removes one. Not cached. Vault (Vault/, Chat/VaultPrompt.swift, Chat/ChatThread+Vault.swift): `AppModel.vault(for:)` gives a `VaultList` per Bot: `refresh()` (`vault.list` and `vault.sources`), `add(_:allowingUnencrypted:)` (`VaultDraft`: `.login`, `.payment`, `.address`), `remove`, `setEnabled`, `unlock(_:password:allowingUnencrypted:)` (45 s), `lock`. Every call sends `profile`. `VaultItem` and `VaultSource` are metadata; only local items are removable. In chats `AppModel.handle` routes `vault.unlock_prompt`, `vault.save_login` and `vault.code` to `ChatThread.vaultPrompts` (`VaultPrompt`) before the 4404 fallback, and answers `VaultPrompt.skipped` (`{"value": ""}`) when no card can be shown. `ChatThread.answer(_:secret:identifier:allowingUnencrypted:)` returns false and sends nothing if the value is incomplete or the gateway is plain http without consent; a login's answer is JSON `{identifier, password}`. `skip(_:)` sends the empty value; `request.cancel` withdraws the card; `attach` adopts open requests and skips unreadable ones; `detach` clears them. Each outcome adds a notice that names the site, never the value. GPT-Live (Voice/VoiceLive.swift): `AppModel.voiceLive` (`VoiceLiveService`) reads `GET /api/audio/voice-live/status?profile=` (`VoiceLiveStatus`: mode `chained`/`gpt-live`, `available`, `reason`, `model`, `voice`) and exchanges a WebRTC offer for the answer via `POST /api/audio/voice-live/session?profile=` (`{sdp, history}` → `transport.sdp`; the SDP is passed byte-exact). `ChatThread.liveHistory()` builds the seed history (latest text turns, ≤24 messages, ~6,000 characters, `input_text`/`output_text`); `delegate(_:spokenContext:)` stops a running reply, then sends the words as your message with `surface: voice-live` and `voice_context` (`submit` takes extra params). Agent defaults (Chat/ChatModel.swift): `makeModelDefault(confirmed:)` sends the chat's model to `profiles.configure {name: contactID, model, provider}` (returns `ModelSwitch`; `.needsConfirmation` for `confirm_required`, resend with `confirm_expensive_model`; `applied.model == false` → `.failed`) and adds a notice; `makeReasoningDefault()` sends `config.set key: reasoning, scope: global, profile: contactID`. `/reasoning … --global` also passes `profile`, because `config.set` writes the profile named in `profile`, else the gateway's main one. Undo and edit (Chat/ChatThread+Edit.swift): `lastSent` is your newest message; `canRewind` is true between replies when nothing uploads or rewinds (`isRewinding`). `undo()` calls `session.undo` and, when it `removed` anything, reloads with `session.history` (`replaceTranscript(with:)`, bumping `transcriptLoad`), else cuts the local transcript (`ThreadState.rewind(from:)`); a refusal or nothing to undo becomes a notice. `edit(_:)` is undo then `send`; a failed undo puts the text in `prefill`. `editableText(of:)` keeps the text and `@file:` lines, not `@image:` lines. Model and thinking (Chat/ChatModel.swift): `ChatThread.model` (`ChatModel`: name, provider, `ReasoningLevel?`) comes from the `info` of `session.resume`/`session.create` and from `session.info` events (`reasoning_effort` "" = provider default → `nil`, "none" = `.off`). `loadModels()` reads `model.options {session_id}` into `modelProviders` (`ModelProvider`: slug, name, `featured_models` when an aggregator has them else `models`, `reasons(_:)` from `capabilities`). `setModel(_:provider:confirmed:)` sends `config.set key:model value:"<model> --provider <slug> --session"` (this chat only; config.yaml untouched) and returns `ModelSwitch` (`.switched`, `.next` when deferred during a reply, with a notice; `.needsConfirmation(message)` for `confirm_required`, resend with `confirmed` → `confirm_expensive_model`; `.failed`); a `warning` becomes a notice. `setReasoning(_:)` sends `config.set key:reasoning`, shows the level at once and reverts with a notice on failure. Masked prompts (Chat/SecretPrompt.swift, Chat/ChatThread+Secrets.swift): `ChatThread.secrets` holds `SecretPrompt`s from the `secret` and `sudo` server requests (live, or `open_requests` on attach; cleared on detach, removed on `request.cancel`; never cached). `answer(_:with:)` sends `{value}`, `skip(_:)` sends `{value: ""}`, and notices name the variable, never the value. `isLinkUnencrypted` comes from `GatewayAddress.isUnencrypted` through the `gateway` closure AppModel sets. `AppModel.media` (`MediaStore`) reads files agents name in chats through `GET /api/fs/read-data-url?path=&profile=` (16 MB cap; `/api/media` only serves the default profile's image folders), keeps the last 40 in memory and shares one request per file; `AppModel.describe` words errors for the UI. AppModel exposes restore/signIn (`isRestoring` is true from launch while a saved gateway's sign-in is being read, for the splash), `AppModel.demo()` (Debug only: a signed-in model with made-up agents, chats, a pending approval, a secret prompt in Ops, a sudo prompt in Ledger with the plain-http warning, a room and routines, built from the internal `sample` helpers; it never connects), `setForeground(_:)` (closes the socket while the app is in the background and reconnects on return, reattaching every chat; the iOS app calls it from `scenePhase`) and per-contact thread/room/routine operations. GatewayConnector mints a WebSocket ticket, opens /api/ws, waits for gateway.ready, then advertises server_requests capabilities. JSONRPCChannel owns socket requests and responses. OfflineCache persists a Codable roster/thread snapshot; KeychainTokenStore persists token sets per gateway.
